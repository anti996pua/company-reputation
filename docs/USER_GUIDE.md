# 用户使用指南

> 作者：产品经理
> 版本：v4.3

📖 **界面语言**：站点界面支持 10 种语言（中文/English/日本語/한국어/Français/Deutsch/Español/Português/Русский/繁體中文），通过导航栏下拉菜单切换。

## 什么是公司信誉查询系统？

公司信誉查询系统是一个方便快捷的企业口碑查询平台。想了解一家公司的真实工作情况？加班多吗？福利怎么样？企业文化如何？在这里都可以找到答案。

## 快速开始

### 1. 搜索公司

在首页搜索框中输入公司名称：

- 输入"华为"、"字节跳动"等公司名
- 输入过程中会自动弹出搜索建议
- 点击建议项直接跳转，或按回车查看全部结果

### 2. 查看搜索结果

搜索结果会以列表形式展示每家公司的：
- **名称**和**简介**
- **综合评分**和**点评数量**
- **所在城市**、**公司规模**、**所属行业**

结果按匹配度排序，最相关的公司排在最前面。

### 3. 切换暗色/亮色模式

点击页面顶部导航栏的 🌙/☀️ 按钮切换暗色模式。选择会保存在浏览器中，下次打开自动沿用。

页面首次加载时会自动检测系统主题偏好（`prefers-color-scheme`）。

### 4. 浏览部门详情（大公司适用）

像华为这样的大公司可能分为多个业务部门。以华为为例：

- **公司总览页** (`c/华为.html`) 显示公司基本信息 + 下属部门卡片列表
- 点击部门卡片可进入该部门的**独立详情页**

部门页面通过**面包屑导航**（首页 › 华为 › 终端业务部）方便您随时返回上级。

部门页面同样包含完整的 8 项指标评分、描述文本、优缺点和评论区。

### 5. 搜索部门和公司

在搜索框中输入关键词，搜索结果会同时展示**公司**和**部门**：

- 部门名称后带有其所属公司的标签，例如："终端业务部 `华为`"
- 部门结果左侧有蓝色竖线标识，与公司结果区分
- 点击部门结果直接跳转到该部门的详情页

### 6. 浏览公司详情

点击任意公司进入详情页，您将看到：

#### 🏢 公司基本信息
- 公司全称、英文名、所属行业
- 所在城市、公司规模
- 成立年份、官方网站链接
- 公司简介

#### ⭐ 综合评分
页面右上角的大圆环显示公司的综合评分（满分 5 分）。

#### 📊 八大指标详解

| 指标 | 说明 | 分数越高表示... |
|---|---|---|
| 工作强度 | 工作任务的密度和压力 | 强度越大 |
| 加班频率 | 加班的时间和频率 | 加班越多 |
| 薪资水平 | 薪酬待遇的竞争力 | 薪资越高 |
| 福利待遇 | 各种福利的完善程度 | 福利越好 |
| 工作生活平衡 | 工作与个人生活的界限 | 平衡越好 |
| 职业发展 | 晋升和成长的空间 | 发展越好 |
| 工作环境 | 办公条件和氛围 | 环境越好 |
| 企业文化 | 公司价值观和文化氛围 | 文化越好 |

#### ⚠️ 996 警示
如果该公司被标记为 996 工作制，会显示黄色的警示条。

#### 📝 详细描述
- **加班情况**：日常加班时长、周末频率等真实描述
- **福利待遇**：薪资构成、餐补、房补、保险等具体福利
- **企业文化**：内部氛围、管理风格等软性信息
- **优点和缺点**：员工视角的真实评价

### 7. 查看职位信息 v4.0

在部门详情页的`💼 招聘职位`区，您可以浏览该部门正在招聘的职位：

- 职位卡片显示：职位名称、类别、职级范围、工作地点、薪资概览
- 点击进入**职位详情页**，查看：
  - **薪资范围**：按职级列出月薪和年终范围
  - **技术栈**：使用的技术标签（编程语言、框架、工具）
  - **任职要求**：学历、经验、技能要求清单
  - **面试流程**：从投递到 offer 的完整步骤
- **类似职位**区推荐其他公司的同类职位，方便横向对比

### 8. 阅读员工评价 v4.0

公司/部门详情页的`💬 员工评价`区展示在职/前员工的真实反馈：

- 每条评价显示：发布日期、评价者角色、工作年限、署名
- **评分**：该员工的打分（1-5 分）
- **引言**：一句话概括（`>` 引用格式）
- **优点卡**（绿色边框）：好的方面
- **缺点卡**（红色边框）：需要改进的方面
- 按日期降序排列，最新的在最上面

### 9. 跨公司对比 v4.0

想比较几家公司的指标？使用 🔀 对比功能：

**添加公司：**
- 在公司/部门详情页点击 **🔀 对比** 按钮
- 或在对比页搜索框输入公司名
- 最多添加 **4 家公司/部门**

**查看对比：**
- 点击顶部导航栏 **🔀 对比** 链接进入对比页
- 15 行对比表：综合评分、城市、规模、行业、8 项指标、职位数量
- 选中的公司会保存到浏览器，关闭页面后重新打开仍在
- 分享对比：复制 URL（`compare.html?q=华为,腾讯`）

**移除公司：** 在对比页点击 ❌ 按钮。添加/移除/清空操作会弹出 toast 提示（取代传统 alert）。

### 10. 一键跳转编辑 v4.0

## 如何添加/编辑公司数据

本项目使用 **Markdown 文件** 存储公司数据（类似 linux-command 项目）。要添加新公司或编辑已有数据：

### 对于用户（通过 GitHub）

1. 在仓库的 `companies/` 目录下操作
2. 创建新的 `.md` 文件或编辑已有文件
3. 遵循下面的格式
4. 提交 Pull Request

### Markdown 格式说明

每个公司一个 Markdown 文件，放置在 `companies/` 目录下。格式如下：

```markdown
公司名称
===

公司简介文字（一段话描述这家公司是做什么的）

## 基本信息

- 英文名：ByteDance
- 别名：ByteDance, 抖音, TikTok
- 城市：北京
- 规模：10000人以上
- 成立：2012
- 行业：互联网/科技
- 官网：https://www.bytedance.com

## 工作强度

评分：4.5/5

## 加班频率

评分：4.2/5

## 是否996

是

## 薪资水平

评分：4.8/5

## 福利待遇分

评分：4.0/5

## 加班情况

描述文字...

## 优点

优点文字...

## 缺点

缺点文字...
```

### 部门 Markdown 格式（大公司分部门管理）

大公司可以将不同部门写在**子目录**中。以华为为例：

```
companies/
├── 华为.md              # 公司总览（基本信息 + 概述）
└── 华为/                # 部门目录
    ├── 终端业务部.md
    ├── 云计算.md
    ├── 海思半导体.md
    └── 2012实验室.md
```

部门文件的格式与公司文件类似，但需注意：

**部门文件的标题**应为 **"公司名 - 部门名"** 格式（构建时自动使用文件名作为短名称）：

```markdown
华为 - 终端业务部
===

华为消费者业务的旗舰部门，负责手机、平板等终端产品。

## 基本信息

- 所属公司：华为           ← 必填，指定父公司
- 城市：深圳（总部）/ 北京  ← 可与父公司不同
- 部门规模：约 5 万人       ← 使用"部门规模"代替"规模"
- 业务范围：手机、平板、PC  ← 使用"业务范围"代替"行业"

## 工作强度

评分：4.5/5

## 加班情况

描述文字...

## 优点

优点文字...
```

**注意事项**：
- 公司总览文件 (`华为.md`) 只需写基本信息 + 概述，无需写评分指标（部门页面会展示详细指标）
- 公司总览页**自动显示**下属部门列表（按文件名排序），无需手动维护
- 部门文件中的 `## 基本信息` 使用 `所属公司`、`部门规模`、`业务范围` 等字段
- 部门数据显示在搜索结果中，名称显示为"华为 - 终端业务部"，并带有公司标签

### 评分规则

- 每个指标使用 **0-5 分**（0=最差，5=最好）
- "是否996" 字段填写"是"或"否"
- 带评分的指标必须在内容第一行包含 `评分：X.X/5`
- 描述性章节（加班情况、福利待遇、企业文化、优点、缺点）为纯文本内容
- **公司总览文件可以没有评分指标**（如有部门，自动隐藏评分区域；如无部门，仍正常显示评分）

### 员工评价 Markdown 格式 v4.0

在 `## 员工评价` 区块下添加多条评价：

```markdown
## 员工评价

### 2024-03-15 | 高级工程师 | 3 年 | @huawei_insider

> 进来之前在网上看了很多评价都说压力大。

评分：4.0/5

**优点**
薪资有竞争力，技术成长快

**缺点**
工作强度大，部门墙严重
```

格式规则：
- `### YYYY-MM-DD | 角色 | 经验 | 作者`：标题行，四条信息用 `|` 分隔
- `>` 引用：评价引言
- `评分：X.X/5`：该条评价打分
- `**优点**` / `**缺点**`：可选优点/缺点块

### 职位 Markdown 格式 v4.0

放在 `companies/公司/部门/positions/` 目录下：

```markdown
嵌入式软件工程师
========================================

负责嵌入式系统驱动与固件开发。

## 基本信息

- 类别：技术
- 职级范围：13-16 级
- 工作地点：深圳/东莞

## 薪资范围

- 13 级：25-35K × 14-16 薪
- 14 级：35-50K × 14-16 薪

## 技术栈

- C / C++ / Rust
- RTOS / Linux Kernel

## 任职要求

- 计算机相关专业本科及以上
- 5 年以上嵌入式开发经验

## 面试流程

1. 简历筛选
2. 在线笔试
3. 技术一面

## 类似职位

- 腾讯/IEG/天美工作室/positions/嵌入式开发工程师 - 腾讯 IEG 嵌入式开发
```

格式规则：
- 分隔符 `===` 支持任意数量 `=`（兼容 `===` 和 `================`）
- `## 基本信息`：类别/职级范围/工作地点/招聘人数
- `## 薪资范围`：每行 `- 职级：金额`
- `## 技术栈`：每行 `- 标签`（支持 `编程语言：` 分类前缀）
- `## 任职要求`：每行 `- 要求`
- `## 面试流程`：`1. 步骤` 格式，编号从 1 开始
- `## 类似职位`：每行 `- path - title`，path 对应其他职位文件路径

### 添加公司/部门/职位图片 v4.3

在 `.md` 文件同级目录下创建 `img/` 文件夹，放入图片文件：

```
companies/
├── 华为.md
└── 华为/
    ├── img/cover.svg        ← 公司图片（显示在华为详情页）
    ├── 终端业务部.md
    ├── 终端业务部/
    │   └── positions/
    │       └── 嵌入式软件工程师.md
    └── 终端业务部/           ← 职位图片目录（与 .md 文件名同名的目录）
        └── 嵌入式软件工程师/
            └── img/workspace.png
```

支持的格式：`svg`、`png`、`jpg`、`jpeg`、`gif`、`webp`。图片会展示在详情页的图片画廊中。

### 公司图标 v4.3

在 `images/companies/` 下创建 `{公司名}.svg` 作为公司图标（40×40），显示在公司详情页标题旁和搜索结果中。未提供则使用默认图标。

## 常见问题

### Q: 数据来自哪里？
数据由用户自愿贡献整理，仅供参考。我们不对数据的绝对准确性负责。

### Q: 如何报告错误信息？
在 GitHub Issues 中报告，或在讨论区留言。

### Q: 综合评分是怎么计算的？
综合评分 =（薪资水平 + 福利待遇 + 工作生活平衡 + 职业发展 + 工作环境 + 企业文化）÷ 6

### Q: 为什么有些公司页面没有评分指标？
像华为这样有下属部门的大公司，公司总览页不展示具体评分指标（各部门页面有完整评分）。没有部门的小公司仍正常展示评分。

### Q: 如何添加新部门？
在 `companies/父公司名/` 目录下创建 `.md` 文件，格式与公司文件相同，但 `## 基本信息` 中使用 `所属公司`、`部门规模`、`业务范围` 等字段（见上文格式说明）。然后运行 `npm run build`。

### Q: 部门名称可以重复吗？
不能。部门文件必须放在各自父公司的子目录下（`companies/华为/`、`companies/字节跳动/` 等），不同公司的部门可以使用相同名称。

### Q: 部门可以嵌套多深？v4.0
任意深度。例如：华为/终端BG/手机产品线/上海研发中心（深度 3）。构建脚本 `scanTree()` 递归扫描无深度限制。

### Q: 如何添加职位数据？v4.0
在部门目录下创建 `positions/` 子目录，放入职位 `.md` 文件。格式见"职位 Markdown 格式"章节。重新构建或 dev 自动重建即生效。

### Q: 如何添加员工评价？v4.0
在公司/部门 `.md` 文件中添加 `## 员工评价` 区块，按"员工评价 Markdown 格式"章节添加条目。构建时自动解析。

### Q: 什么是对比模式？v4.0
最多选择 4 家公司/部门并排比较 15 项指标（评分、城市、规模、行业、8 项指标、职位数）。选择持久化到浏览器，可分享 URL。

### Q: ✏️ 编辑链接是做什么的？v4.0
一键跳转到 Git 仓库上的 Markdown 源文件，方便数据贡献者直接编辑。仓库基地址通过 `config.json` 中的 `sourceBase` 配置。

### Q: 为什么有些公司没有评分？
新添加的公司或数据不完整的公司可能暂时没有评分。

## 使用建议

1. **多方参考**：不要只看评分，请仔细阅读详细的文字描述
2. **关注时效**：公司状况可能随时间变化，注意查看数据的更新时间
3. **理性看待**：每个员工的体验可能不同，综合多方意见更客观
4. **贡献力量**：如果你了解某家公司，欢迎创建 Markdown 文件贡献数据
