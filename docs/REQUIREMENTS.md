## 需求管理规范

### 需求分层

| 层级 | 粒度 | 周期 | 标识前缀 |
|------|------|------|----------|

| 等级 | 定义 | 处理要求 |
|------|------|----------|
| P0 | **阻塞**：功能阻断、数据错误、安全漏洞 | 立即修复，阻塞发布 |

## 1. 项目概述

### 1.1 项目背景

参考 [linux-command](https://github.com/jaywcjlove/linux-command) 项目的设计理念（Markdown 数据源 + 静态站点生成 + 多平台部署），构建一个公司信誉查询系统。用户可通过公司名称搜索企业信息，查看工作强度、加班情况、福利待遇等多项指标，并参与评论讨论。

### 1.2 项目目标

- 提供一个**无需数据库**的静态站点解决方案
- 数据以 **Markdown 格式**存储，用户可直接编辑添加
- 支持**多语言**界面（中文 / English / 日本語）
- 可部署到 **GitHub Pages、Docker、Vercel、Netlify** 等平台

### 1.3 参考项目

- [linux-command](https://github.com/jaywcjlove/linux-command) — Markdown 格式命令手册，静态站点生成器
- 本项目的构建脚本 `scripts/build.mjs` 参考了 linux-command 的 `scripts/build.mjs`

### 1.4 术语表

| 术语 | 说明 |
|---|---|---|
| 静态站点 | 预先生成的 HTML/CSS/JS 文件，无需服务器端运行时 |
| Markdown 数据源 | 以 `.md` 文件格式存储的结构化数据 |
| 996 | 早 9 点至晚 9 点、每周 6 天的工作制度 |
| i18n | 国际化（Internationalization） |
| Giscus | 基于 GitHub Discussions 的评论系统 |
| EJS | Embedded JavaScript 模板引擎 |
| 部门（Dept） | 大公司下属的独立业务单元，有单独 Markdown 文件和详情页 |
| 暗色模式（Dark Mode） | 网页暗色主题，通过 `data-theme` CSS 变量 + `localStorage` 实现 |

## 2. 用户角色

### 2.1 普通用户（求职者/职场人）

- 搜索公司，查看信誉评分和详细指标
- 切换语言界面
- 通过 Giscus (GitHub 账号) 发表评论

### 2.2 数据贡献者

- 创建/编辑 Markdown 文件添加公司数据
- 提交 GitHub Pull Request

### 2.3 项目维护者

- 管理 `companies/` 目录下的 Markdown 文件
- 运行构建命令生成静态站点
- 部署到目标平台

### 5.4 综合评分计算

综合评分 =（薪资水平 + 福利待遇 + 工作生活平衡 + 职业发展 + 工作环境 + 企业文化）÷ 6

结果保留一位小数。
