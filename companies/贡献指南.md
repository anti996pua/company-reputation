贡献指南 — 如何添加公司数据
=======================

欢迎！本文档是一份"活的"模板，手把手教你如何在本站添加一家公司。每个 `##` 章节后面都有一个对应的 `## 📖 填写说明` 章节，解释了该字段的填写方法和注意事项。

**快速开始**：
1. 复制 `companies/华为.md` 或本文件
2. 清空所有 `📖 填写说明` 章节和本说明段落
3. 填入你的公司真实数据
4. 运行 `npm run build` 验证

---

## ⚠️ 隐私保护 — 必读

贡献数据时请注意保护个人隐私和公司敏感信息：

| 禁止填写 | 说明 | 替代方案 |
|----------|------|----------|
| 真实姓名、工号 | 不要出现"张三（工号 12345）" | 用化名如"匿名工程师" |
| 手机号、邮箱 | 不要在评价中暴露个人联系方式 | 留空或填写"匿名" |
| 内部系统截图 | 可能包含内部 URL、版本号等 | 用文字描述代替 |
| 未公开的薪资数据 | 不要泄露公司未公开的薪资结构 | 模糊范围如"25-50K" |
| 敏感商业信息 | 未公开的业务数据、战略规划 | 只写公开可查的信息 |
| 负面评价中的人身攻击 | 针对具体个人的批评 | 针对制度和流程本身 |

**原则**：你写的评价是对制度和文化的描述，不是对个人的投诉。好的评价应该让后来者了解真实工作环境，同时不会暴露你的身份。

## 📖 填写说明

`## 基本信息` 中的每一行是一个数据字段，格式固定为 `- 字段名：值`。

| 字段 | 是否必需 | 说明 | 示例 |
|---|---|---|---|
| `英文名` | 推荐 | 用于英文搜索匹配 | `Huawei` |
| `日文名` | 推荐 | 用于日文搜索匹配 | `ファーウェイ` |
| `别名` | 推荐 | 逗号分隔，支持多名称搜索 | `Huawei, 华为技术` |
| `标签` | 推荐 | 用 `/` 分隔，用于分类和搜索 | `通信设备/5G/大厂/深圳` |
| `城市` | 推荐 | 公司总部城市 | `深圳` |
| `规模` | 推荐 | 公司规模 | `约 19.5 万人` |
| `成立` | 推荐 | 成立年份（纯数字） | `1987` |
| `行业` | 推荐 | 所属行业 | `互联网/科技` |
| `官网` | 推荐 | 官方网址 | `https://www.huawei.com` |

所有字段都可以省略，但填得越多搜索匹配效果越好。

## 📖 评分填写说明

每个评分指标格式：`评分：X.X/5`，评分范围 1.0 - 5.0。

| 评分 | 含义 |
|---|---|
| 5.0 | 极高（如 996、长期通宵）|
| 4.0 | 较高（经常加班）|
| 3.0 | 中等（偶尔加班）|
| 2.0 | 较低（基本不加班）|
| 1.0 | 很低（955 工作制）|

评分指标说明：

| 指标 | 关注点 |
|---|---|
| `工作强度` | 任务量和压力水平 |
| `加班频率` | 加班的频繁程度（侧重频率） |
| `是否996` | 填 `是` / `否` / `部分部门是` |
| `薪资水平` | 相对市场水平 |
| `福利待遇分` | 五险一金、补贴、股票等 |
| `工作生活平衡` | 个人时间保障程度 |
| `职业发展` | 晋升通道、培训资源 |
| `工作环境` | 办公环境、设备配置 |
| `企业文化分` | 价值观、管理风格 |

评分后面可以跟一段描述文字说明具体情况：

```
评分：4.5/5

终端业务因产品竞争激烈，发布前普遍进入封闭开发模式，项目攻坚期 10-10-6 是常态。
```

## 💡 添加部门

在公司目录下创建子目录来添加部门：

```
companies/
├── 华为.md
├── 华为/
│   ├── 终端BG.md
│   ├── 终端BG/
│   │   ├── 手机产品线.md
│   │   └── positions/
│   │       └── 嵌入式软件工程师.md
├── 腾讯.md
└── 腾讯/
    ├── IEG.md
    └── IEG/
        └── 天美工作室.md
```

**规则**：
- 目录名和 `.md` 文件名通常一致（如 `华为/终端BG/终端BG.md`）
- 支持任意深度嵌套
- 部门标题格式：`公司 - 部门` 或 `公司 - 上级部门 - 部门`

部门文件与公司文件格式完全一致，额外支持 `- 所属公司：华为` 字段。

详细示例请看本公司的 `示例部门`。

## 💡 添加职位

在公司或部门下创建 `positions/` 目录来添加职位：

```

├── 嵌入式软件工程师.md
├── 前端开发工程师.md
```

**职位必需章节**：`薪资范围` `技术栈` `技能要求` `面试流程` `类似职位`

详细示例请看 `示例部门` 下的 `示例职位`。

## 💡 多语言搜索

填好以下字段即可支持多语言搜索：

- `英文名` → 让英文搜索匹配（如 `Huawei`）
- `日文名` → 让日文搜索匹配（如 `ファーウェイ`）
- `别名` → 额外的名称变体（如 `Huawei, 华为技术`）

搜索优先级：中文名 > 英文名 > 日文名 > 别名 > 标签

## 🤖 使用 opencode 贡献数据

如果你使用 opencode 作为 AI 编程助手，可以直接让 AI 帮你完成数据贡献。以下是一些参考提示词：

### 添加新公司

```
在 companies/ 目录下创建 理想汽车.md，包含以下内容：
- 基本信息：英文名 Li Auto，城市 北京，规模 约 3 万人，行业 新能源汽车/智能驾驶
- 工作强度 4.0/5，加班频率 4.0/5，是否996 是
- 薪资水平 4.0/5，福利待遇 3.5/5
- 加班情况、福利待遇、企业文化各写一段真实风格的描述
- 优点和缺点各列出 3-5 条
- 格式参考 companies/华为.md
完成后运行 npm run build 验证
```

### 添加部门

```
在 companies/理想汽车/ 下添加部门 整车研发，包含：
- 基本信息：所属公司 理想汽车，部门规模 约 8000 人，业务范围 整车设计/研发
- 工作强度 4.5/5，加班频率 4.0/5
- 优点和缺点各 3 条
完成后运行 npm run build
```

### 添加职位

```
在 companies/理想汽车/整车研发/positions/ 下添加 智能座舱开发工程师.md：
- 基本信息：类别 技术，职级范围 P5-P8，工作地点 北京
- 薪资范围、技术栈、技能要求、面试流程、类似职位各写 3-5 条
- 类似职位引用其他公司的已有职位
完成后运行 npm run build 验证
```

### 添加员工评价

```
在 companies/理想汽车.md 的「员工评价」区添加一条评价：
- 日期 2025-06-01，角色 高级工程师，工作年限 2 年
- 评分 4.0/5
- 优点：新能源赛道前景好，股票期权有价值
- 缺点：生产交付压力大，部分管理流程混乱
- 注意隐私：不要出现真实姓名和联系方式
完成后运行 npm run build
```

### 修改现有数据

```
打开 companies/理想汽车.md，把工作强度评分从 4.0 改为 3.5，
更新加班情况描述为更详细的版本，保持其他内容不变。
完成后运行 npm run build 验证
```

### 提示词技巧

| 要素 | 说明 | 示例 |
|------|------|------|
| 明确操作 | 创建/修改/删除哪个文件 | `在 companies/ 下创建 xxx.md` |
| 指定格式 | 参考哪个已有文件 | `格式参考 华为.md` |
| 验证步骤 | 要求运行构建验证 | `完成后运行 npm run build` |
| 隐私要求 | 明确要求不包含个人信息 | `注意不要出现真实姓名` |
| 范围限制 | 明确什么改什么不改 | `保持其他内容不变` |
